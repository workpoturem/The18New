# Сборка и деплой

Проект собирается в `build/`, а скрипт деплоя переносит результат в соседнюю папку `../the18_site`.
Скрипт не очищает папку сайта: он обновляет только файлы из `build/` и перечисленные runtime-файлы
из `public/`. Каталоги `1preview`, `studio`, файл `.htaccess` и любые остальные файлы сайта вне этого
списка сохраняются.

## Команды

Из каталога `the18_dev`:

```sh
npm install
npm run build
npm run deploy
```

`npm run deploy` сам выполняет production-сборку, поэтому отдельный `npm run build` перед ним нужен только
для самостоятельной проверки сборки. Скрипт деплоя использует только встроенные модули Node.js и не
устанавливает дополнительные зависимости.

После деплоя на хостинг загружается **содержимое папки `the18_site`**, а не каталог `the18_dev` и не
отдельно папка `build`. Содержимое `the18_site` включает сохранённые хостинговые файлы и обновлённые
файлы приложения.

## Обновление Buy / Demo — Paddle Classic

Номера товаров и продавец `112127` сохранены. База Firebase не менялась.
В проверенных 29 публичных карточках `buyId`/`demoLink` — числовые значения или строки с числами.
Paddle распознаёт `901901` как SphereUI Kit Crypto [Regular], `901903` — [Demo].
Это подтверждает наличие товаров, **но не прохождение оплаты**.

Для числовых товаров применяется **Paddle Classic**, а не Paddle Billing v2:

- библиотека с официального CDN: `https://cdn.paddle.com/paddle/paddle.js`;
- один вызов `Paddle.Setup({ vendor: 112127, ... })`;
- окно внутри сайта: `Paddle.Checkout.open({ product: ID, method: 'overlay' })`;
- Buy и Demo передают каждый свой ID. Цена и выдача файлов остаются на стороне Paddle.

Этот API использовался и в исходном коде. Сам по себе переход Paddle к Billing
не доказывает причину сообщённого сбоя. Для полного диагноза нужен результат
нажатия кнопки на опубликованном сайте; интерактивную проверку провести не удалось.

### Что изменено

`public/paddle-checkout.js` проверяет доступность SDK, инициализацию и ID.
Принимаются числа, строки с цифрами и простые ссылки
`https://buy.paddle.com/product/ID` (также написание `buy-paddle.com` из вашего примера).
Из ссылки извлекается только ID: перехода на эти адреса нет. Ссылки с параметрами,
чужими доменами или другими путями отклоняются, чтобы не потерять условия оплаты.
При ошибке выводится сообщение вместо необработанного исключения; автоматических
повторных открытий нет. Данные покупателя и события оплаты не записываются в лог.

Порядок загрузки: CDN → адаптер → React bundle. Адаптер обслуживает и старые
вызовы `Paddle.Checkout.open` из готового bundle, и обновлённый React-компонент.
Поэтому минифицированный `bundle.js` не редактировался. Webpack выдаёт адаптер
отдельным файлом и при разработке, и при production-сборке.

### Публикация без Node.js и пересборки

Для существующей версии сайта обновлены/подготовлены:

1. `the18_site/paddle-checkout.js` — сначала загрузить в корень сайта.
2. `the18_site/index.html` — затем заменить файл в корне сайта.

Перед заменой сохраните копию прежнего `index.html` вне публичной папки хостинга.
Это локальная подготовка файлов: автоматической загрузки на удалённый хостинг нет.
Не заменяйте корневой `index.html` старой копией из `the18_site/build/`.
При полном размещении загружайте содержимое `the18_site`, сохраняя `.htaccess` и изображения.

### Проверка после загрузки

1. Обновить страницу с очисткой кэша. Открыть `/uiux/sphereui_crypto` напрямую.
2. Buy должен открыть SphereUI Kit Crypto [Regular] с ID `901901`.
3. Закрыть окно, нажать Demo — должен открыться [Demo] с ID `901903`.
4. Проверить ещё один товар и бесплатный Download. ID не подменяются друг другом.
5. Для проверки открытия окна не нужно вводить платёжные данные или завершать заказ.

В Paddle Classic проверьте **Checkout → Request Domain Approval / Approved Domains**:
фактический домен сайта должен быть одобрен. Если используется `the18.studio`,
одного одобрения старого `the18.design` недостаточно. Не обходите ограничения Paddle:
ошибки аккаунта, неподтверждённого домена или недоступного региона не исправляются заменой URL.
При отказе пришлите текст ошибки без email, реквизитов карты и других личных данных.

### Локальные проверки

Из `the18_dev` выполнено:

```sh
osascript -l JavaScript tests/paddle-checkout.test.js
```

48 проверок прошли с имитацией SDK: раздельные Buy/Demo, старый bundle,
URL/ID, ошибочные значения, отсутствующий SDK, ошибки инициализации,
повторная загрузка, отсутствие автоматических повторов. **Это не реальный платёжный тест.**
При наличии Node тот же набор запускается через `npm run test:paddle`.
Полная webpack-сборка не проверена: Node.js/npm отсутствуют. Lint/typecheck не настроены.
